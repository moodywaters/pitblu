# v0.2.0 device-foundation plan

Status: complete

## Scope

- Production Bleak adapter for the confirmed Weber iGrill V202 protocol.
- Scheduled continuous discovery using the agreed scan cadences.
- Four logical probe channels with separate presence and availability.
- Explicit desired and observed connection state machine.
- Deterministic simulator with one to four probes and injected device conditions.
- Sanitised recorded BLE fixture derived from accepted physical evidence.

REST, MQTT, SQLite, service deployment and the full resilience controller are excluded.

## Acceptance checklist

- [x] Physical and simulated implementations satisfy one typed adapter boundary.
- [x] The production adapter reads battery plus all four probe characteristics.
- [x] Discovery is scheduled rather than continuously occupying the BLE radio.
- [x] State transitions, repeated requests, backoff cap and jitter are tested without waiting.
- [x] The simulator covers patterns, insertion, removal, battery, stale data and connection loss.
- [x] The recorded fixture contains no Bluetooth or LAN address and replays the accepted payloads.
- [x] Formatting, linting, strict typing and hardware-independent tests pass locally.
- [x] `pitboss-v202-check` succeeds on the target Raspberry Pi against the physical V202.
- [x] Two attached probes match the V202 display and the remaining channels report absent.
- [x] The v0.2.0 result is documented, committed, pushed and tagged.
