# v0.5.0 resilience

Status: candidate passed 84 local tests at 93.99 per cent coverage, lint, format and strict typing;
Raspberry Pi acceptance pending

## Implementation and acceptance

1. Supervise MQTT connection failures with safe status, bounded retry backoff, session identity,
   retained-state resynchronisation and bounded offline shutdown.
2. Serialise BLE actions, make duplicate control requests idempotent, cancel recovery on explicit
   disconnect and bypass backoff on reconnect. Restore registered desired connections after restart
   using protected stable identity, never automatic name-only matching to unregistered hardware.
3. Continue after transient reads, degrade after configured failures and reconnect after the
   no-valid-reading deadline. Reset backoff only after stable operation.
4. Persist bounded operational events, mark interrupted operations on restart, expose safe
   diagnostics and stop all tasks before closing resources. Preserve desired connection state.
5. Test recovery, concurrency, persistence, redaction and shutdown with controlled time/fakes.
   Run lint, formatting, strict typing and the coverage gate before Pi delivery.
6. Verify broker restart, invalid credentials, device recovery, explicit disconnect, application
   restart and shutdown on the Pi before release. Do not advance to native deployment.

The current single-adapter service will explicitly reject simultaneous ownership by another device.
Persisting multiple registrations must never permit reading one device under another device ID.
No new runtime dependency is planned. Documentation and handoff updates accompany the code.

## Pi gate

- Install the candidate and pass lint, formatting, strict typing and tests.
- Verify MQTT diagnostics with unavailable broker, then restore the broker and observe recovery.
- Verify a wrong credential gives safe status; correcting the stored secret requires restart.
- Verify a registered simulator restores after application restart; explicit disconnect persists.
- Verify physical V202 power-cycle recovery and probe/display/battery agreement.
- Verify orderly API shutdown with active SSE and offline MQTT retained state.
- Record sanitised evidence before merging, tagging or releasing v0.5.0.

Existing registrations require explicit identity selection before automatic recovery; no name-only
fallback is permitted. Back up the administrative SQLite database before testing the additive
identity migration. The temporary development database and broker credentials stay on the Pi.
