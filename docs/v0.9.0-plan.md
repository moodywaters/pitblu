# v0.9.0 release audit

Status: in progress. Baseline is released v0.6.0. No changes to the running Pi
installation are implied by this audit branch.

## Required work

- Security review of authentication, validation, CORS, disruptive operations,
  diagnostic redaction, persistence and deployment lifecycle.
- Documentation audit against actual behaviour, including the complete
  [frontend and AI integration guide](frontend-integration.md).
- Exact dependency/provenance and licence review, including transitive packages
  and differences between supported Python/platform environments.
- Repeatable clean-Pi installation acceptance on a clean target. Existing-Pi
  upgrade/rollback results are not a substitute. Arrange a spare card/target with
  the operator before changing any live deployment.
- Run the complete hardware-independent checks and supported-Python CI before
  preparing a release candidate. Record physical acceptance separately.

## Frontend handoff audit findings

The v0.6.0 implementation currently has the following integration limitations.
These are verified by source inspection, not new physical measurements:

- Device PATCH clears friendlyName when it is omitted.
- CORS does not expose ETag/correlation response headers to browser JavaScript.
- polling.battery_interval is represented in configuration but does not drive
  an independent acquisition schedule.
- Bluetooth availability is a constant response rather than adapter-health evidence.
- Clock-synchronisation health is not exposed.
- SSE has no replay and bounded queues can drop events; documented reconciliation
  is necessary, not a promise of lossless history.
- Service MQTT availability reuses sequence values; device-topic deduplication
  cannot be applied unchanged to service availability.
- Saved configuration is not an active-runtime snapshot, and there is no remote
  service-restart API. Managed-mode validation adds startup constraints.

Resolve or explicitly disposition findings during the audit. Update the integration
guide alongside any fixes; do not silently assert planned features are implemented.
The documentation inventory test checks coverage of routes, settings and event
types, but does not prove every documented semantic detail.

## Release boundary

The security/licence audits and clean-Pi test are not complete merely because the
frontend guide exists. The complete physical acceptance suite and minimum 16-hour
soak remain mandatory v1.0.0 gates; neither is claimed by this milestone plan.
