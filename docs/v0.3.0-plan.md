# v0.3.0 API and configuration plan

Status: implementation complete; Raspberry Pi API check pending

## Scope

- Versioned REST resources and generated OpenAPI.
- Persistent asynchronous scan and device operations.
- Bearer authentication and administrator-token rotation.
- Complete typed configuration descriptions, validation and transactional updates.
- Write-only secret resources and administrative SQLite persistence.

MQTT, SSE, stale telemetry, full resilience, systemd and native installation are excluded.

## Acceptance checklist

- [x] Liveness is minimal and unauthenticated; protected routes enforce configured authentication.
- [x] Discovery, device administration, connection commands and current telemetry use REST.
- [x] Slow commands return HTTP 202 operation resources with persistent status.
- [x] Registered devices, desired state, operations and configuration survive store reopening.
- [x] Configuration exposes required metadata and rejects stale or partial-invalid updates.
- [x] Non-loopback unauthenticated configuration is rejected.
- [x] Token hashes are salted; rotation invalidates the old token.
- [x] Secret values are absent from responses and redacted validation errors.
- [x] API contract, authentication, idempotency and persistence tests pass without hardware.
- [ ] The simulator-backed API starts and passes health, scan and device checks on the target Pi.
- [ ] v0.3.0 is documented, merged, tagged and released.
