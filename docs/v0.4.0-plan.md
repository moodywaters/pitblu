# v0.4.0 telemetry plan

Status: Raspberry Pi acceptance and final quality gate passed; release pending

## Scope

- Canonical internal telemetry event schema and bounded fan-out.
- MQTT version-one topics, JSON payloads, QoS 1 retention rules and service Last Will.
- Authenticated SSE live stream and recent event history.
- Continuous device sampling and configurable stale-data handling.

Reconnection resilience, concurrency controls, diagnostics, native installation and systemd remain
later milestones.

## Acceptance checklist

- [x] Physical and simulated readings use one canonical event path and identify their source.
- [x] MQTT topics and payloads match the documented independent `v1` contract.
- [x] All MQTT publications use QoS 1; state is retained and temperatures are not.
- [x] Service availability configures a retained unavailable Last Will.
- [x] MQTT accepts no command topics.
- [x] SSE emits canonical events with bounded subscriber queues and idle heartbeats.
- [x] REST, SSE and MQTT report stale device and probe availability without stale numeric values.
- [x] Unit tests cover event, SSE, MQTT, Last Will and stale-state behaviour using fakes.
- [x] The candidate passes tests, lint, format and strict typing on the target Raspberry Pi.
- [x] Simulator SSE and authenticated local Mosquitto publishing are demonstrated on the target.
- [ ] v0.4.0 is merged, tagged and released.
